# 工程文件

給開發這個專案的人與代理看的工作文件。給使用者看的文件在 `docs/`。

| 文件 | 內容 | 什麼時候讀 |
|---|---|---|
| [architecture.md](architecture.md) | 系統怎麼組成：範圍、共同決策、驗收里程碑、測試策略 | 改架構、測試或資料遷移之前 |
| [decisions/](decisions/) | 一個難以回頭的選擇一個檔，附上沒被採用的選項 | 想改掉這類選擇之前 |
| [tickets/](tickets/) | 一張工單一個檔，一張工單是一段可獨立交付的工作 | 挑下一件事做的時候 |

## 怎麼用

- **進度看工單檔在哪個資料夾。** 待做的在 `tickets/`，進行中的在 `tickets/doing/`，完成的在 `tickets/done/`。工單「Blocked by」列的每一張都在 `done/` 時才能開始。編號是名字，不是順序。
- **交付工單的那次變更同時把工單檔移到 `done/`。**
- **驗收結果寫在工單裡。** 每張工單最後的「驗收紀錄」記下交付時實際跑過的驗證與當時的裁決，新的寫在最上面。
- **工單之間用編號互相指稱**，例如「工單 27」，不寫路徑，因為工單會在資料夾之間移動。從工程文件連到 repo 裡其他檔案時，路徑從 repo 根目錄寫起，以 `/` 開頭。
- **發現了但現在不修的問題寫成一張工單**，不要只留在對話裡。
- **決策紀錄接受之後不再改寫。** 之後的決定另寫一份，並把舊的那份狀態改成被取代。
- **做到一半停下來時**，把下一個人需要的東西寫在該工單的「Notes」；沒有對應工單的未完成工作寫在 `handoff.md`，做完就刪掉。
