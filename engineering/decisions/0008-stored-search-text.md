# 0008 — 公開搜尋的正規化文字存在資料庫，寫入時同步維護

**Status:** accepted
**Date:** 2026-10-26

## Context

公開搜尋要比對 HTML 可見文字並做 Unicode case folding，這份正規化原本在 Go 裡即時計算。工單 10 的基準測試顯示，2,000 篇文章時兩個搜尋端點各讀 2,000 列，超過每次請求 200 列的上限。

## Decision

文章的標題、內文、摘要各自正規化後存成三個內部欄位，讓 SQL 在計數與分頁前就精確篩選。欄位在所有寫入路徑的同一筆寫入或交易中維護：GORM 寫入由 callback 處理，匯入連結、媒體網址改寫、備份還原等 raw SQL 路徑明確重算。三個欄位分開比對，不串接，避免跨欄假命中。

## Options rejected

- 每次搜尋時在 Go 裡計算：超過每次請求 200 列的上限。
- 搜尋請求中回填或用背景同步：原始紀錄明訂不採用，理由沒有另外寫下。

## Consequences

搜尋在 SQL 裡完成篩選與分頁。新增任何改寫文章內容的寫入路徑都必須同時重算這三個欄位，無法取得實際字串的 SQL expression 寫入會被拒絕。不經應用程式的外部 SQL 寫入不在保證範圍內。還原含文章的備份時，一律在提交前重建全部文章的搜尋值。
