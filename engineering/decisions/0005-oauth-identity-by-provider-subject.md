# 0005 — 第三方登入以提供者加固定 ID 識別，另存關聯表

**Status:** accepted
**Date:** 2026-10-23

## Context

第三方登入原本只靠 `users.provider` 欄位推算登入方式。第三方帳號的信箱與名稱屬於外部可變資料，帳號也需要連結、解除與重新連結多個提供者。

## Decision

另建 `oauth_identities` 表，以 `(provider, subject)` 精確對到帳號，每個帳號每個提供者最多一個有效關聯，解除時軟刪保留歷史。第三方的信箱與名稱不複製進關聯表，既有帳號不從信箱自動補入第三方 ID。`users.provider` 只代表帳號建立來源。

## Options rejected

- 以第三方信箱對應既有帳號、自動回填關聯：原始紀錄明訂不從信箱回填，理由沒有另外寫下。

## Consequences

登入結果不受第三方改信箱影響。舊帳號要由本人登入後明確連結，不會自動接上。解除綁定不得移除帳號最後一種可用的登入方式。
