# 39 — 作者只能看到與管理自己上傳的媒體

User Story：作者在附件庫只看到自己上傳的檔案，不能改名、搬移、替換或刪除別人的檔案；編輯與管理員照舊管理全部。
Blocked by：無。

## 背景

工單 38 核對驗收里程碑時發現：`internal/server/media_api.go` 的列表、更新、移到回收桶、替換都沒有依 `OwnerID` 過濾，作者可以操作別人的檔案。工單 03 原本有一段媒體所有權草稿，依使用者裁決撤下，結果沒有進 main。

## 要做的事

- 作者呼叫媒體列表、更新、回收、替換時，只能命中 `owner_id` 等於自己的檔案，其他回 404。
- `owner_id` 為空的舊檔案不屬於任何作者。
- 用公開 HTTP 路由與專用 PostgreSQL 補回歸測試，涵蓋作者、編輯、管理員三種角色。

## 驗收

- 作者 A 看不到、改不到作者 B 的檔案。編輯與管理員行為不變。

## 驗收紀錄

- 2026-11-21：新版媒體 API 的列表、修改、回收、替換，舊版檔名 API 的列表、刪除、替換、改名，以及共用同一組處理函式的 `/api/v1/media/files` 都依 `owner_id` 限定作者。沒有擁有者的檔案與磁碟上未登記的檔案，作者一律得到 404，不會被刪除或認領。回歸測試 `TestMediaAuthorsOnlyManageTheirOwnFiles` 在修正前失敗、修正後通過。完整測試 `GORACE=atexit_sleep_ms=0 JELLY_TEST_POSTGRES=1 go test -race -p 1 ./... -count=1` 全部通過，`go vet` 通過。獨立審查沒有 P0 到 P2。
- 沿用的既有行為：作者把自己的檔案改名時，所有文章與商品內文中指向該檔案的網址會一起更新，包括別人的文章，目的是讓連結不中斷。
- 沒有做：後台媒體頁沒有開瀏覽器驗收，這次沒有改畫面程式，作者看到的清單由 API 限定。`/api/v1` 的作者金鑰沒有單獨寫測試，金鑰請求帶入金鑰擁有者的角色（`internal/auth/principal.go`），與後台走同一組處理函式。
