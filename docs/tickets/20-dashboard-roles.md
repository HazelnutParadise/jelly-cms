# 20 — 作者與編輯者使用符合權限的儀表板

Epic：既有待修缺陷
User Story：作者與編輯者開啟儀表板時，只看到可使用的操作，不因讀取管理員設定而發生錯誤。
Blocked by：06、12 已合併；修改 Dashboard 設計板須等待工作單 19 的設計修改結束。
Status：作者隔離站已重現 settings.find 例外及無權操作入口，測試先行。

## 契約與範圍

- 沿用 AdminViewer 的 IsAdmin／Role 與既有導覽角色規則。所有後台人員保留文章與附件入口；新增頁面只顯示給 admin／editor。新增商品及商品／訂單／主題統計只顯示給 admin。
- 非管理員輸出的儀表板 HTML 與腳本不包含管理員限定商品、訂單、設定及主題 API 請求。既有 API 權限與頁面路由不變，不新增公開設定來源。作者可能仍能直接取得頁面編輯殼，實際寫入以既有 API 權限為準。
- 呼叫既有 API 後先檢查 HTTP 成功及真正的回應結構。文章、設定與主題維持陣列檢查後才執行 length／slice／find。商品與訂單為分頁物件，items 必須為陣列、total 必須為非負安全整數；商品顯示 total，訂單依既有「待處理」說明顯示同樣驗證的 counts.pending，不能使用當頁 items.length。失敗保留未知數量的佔位並顯示既有翻譯的載入失敗訊息，不顯示 undefined、虛構為零或假定主題名稱；近期文章失敗須結束載入狀態。不得在失敗後改讀另一個同樣無權使用的 API。
- 管理員成功時維持既有統計與主題名稱顯示，空清單正確顯示零或既有空狀態。沿用現有翻譯與版面，不改權限模型、資料表或相依套件。

## 分工與驗收

- 實作僅 web/admin/index.html 與對應 design/project/Dashboard.dc.html，保留工作單 19 的共同色彩修正。測試代理另建 internal/server/dashboard_roles_test.go，實作者不得修改測試。
- HTTP 驗證 admin／editor／author 的操作、統計與輸出腳本差異，管理員限定 API 對非管理員維持 403。若使用 Node 驗證，執行實際輸出腳本並測試成功、空陣列、非成功回應及非陣列，不能只比對原始碼字串冒充執行結果。
- 主代理在隔離站以作者、編輯者及管理員實際登入，驗證文章載入與允許的導覽、沒有多餘受限請求或 JavaScript 例外，並檢查桌面／手機與亮暗模式。設計板與程式同一提交，線上畫布沿用 design/README.md 的同步流程。
- 完整競態套件、差異審查與必要 CI 全綠後合併清理，不部署。
